## Workflow Automation Management

This section details the API for defining, executing, and tracking multi-step automated workflows.

### Workflow Interaction Endpoints

The following examples assume you have set environment variables for authentication and agent identification:
*   `BASE`: `http://localhost:8000`
*   `TOKEN`: Access Token (e.g., from `localStorage`)
*   `AGENT`: UUID of an existing, active agent.

#### List Workflows

Retrieves a list of all defined workflows for the authenticated user/agent.

```bash
curl -s -H "Authorization: Bearer $TOKEN" $BASE/api/workflows/
```

#### Create Workflow Definition

Defines the structure (nodes and edges) of a new workflow.

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
-H 'Content-Type: application/json' \
-X POST $BASE/api/workflows/ \
-d '{
  "name":"wf-test",
  "description":"test curl",
  "definition":{
    "version":1,
    "nodes":[
      {"id":"n1","type":"agent","agent_id":"'$AGENT'","input":{"query":"{{trigger.query}}"},"position":{"x":0,"y":0},"ui":{"values":{"query":"{{trigger.query}}"}}},
      {"id":"n2","type":"agent","agent_id":"'$AGENT'","input":{"query":"Summarize : {{nodes.n1.output.content}}"},"position":{"x":300,"y":0},"ui":{"values":{}}}
    ],
    "edges":[
      {"source":"n1","target":"n2"}
    ]
  }
}'
# WF=<id returned>
```

#### Retrieve Workflow Details

Fetches the full definition and status of a specific workflow.

```bash
curl -s -H "Authorization: Bearer $TOKEN" $BASE/api/workflows/$WF
```

#### Update Workflow Definition

Modifies the structure or metadata of an existing workflow.

```bash
curl -s -H "Authorization: Bearer $TOKEN" \
-H 'Content-Type: application/json' \
-X PUT $BASE/api/workflows/$WF \
-d '{"name":"wf-test", "description":"v2", "definition":{"version":1,"nodes":[],"edges":[]}}'
```

#### Execute Workflow (Streaming)

Initiates the execution of a workflow and streams real-time status updates via Server-Sent Events (SSE).

```bash
curl -N -H "Authorization: Bearer $TOKEN" \
-H 'Content-Type: application/json' \
-X POST $BASE/api/workflows/$WF/execute/stream \
  -d '{"input_data":{"query":"hello"},"trigger":"manual"}'
```

#### Workflow History and Deletion

Access historical run data and manage workflow lifecycle.

**Get Run History**: Retrieves the history of all execution runs for a workflow.
```bash
curl -s -H "Authorization: Bearer $TOKEN" $BASE/api/workflows/$WF/runs
```

**Get Specific Run Details**: Retrieves detailed information about a specific run.
```bash
curl -s -H "Authorization: Bearer $TOKEN" $BASE/api/workflows/runs/<run_id>
```

**Delete Workflow**: Removes a workflow definition from the system.
```bash
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" -X DELETE $BASE/api/workflows/$WF
# Expected HTTP Code: 204 No Content
```

## 3. Server-Sent Events (SSE) Stream Format

The execution endpoint (`/execute/stream`) uses a real-time stream to communicate the progress of the workflow nodes and agent outputs.

| Event Type | Payload Data | Description |
| :--- | :--- | :--- |
| `init` | `{run_id, workflow_id}` | Initialization event, providing context for the run. |
| `node_status` | `{type, node_id, status:"running"}` | Status update for a specific node currently being processed. |
| `log` or `progress` | `{type:"log"|"progress", data:{message}, node_id}` | Real-time logging and progress messages relayed from the agent. |
| `result` | `{type:"result", data:<payload agent>, node_id}` | The final output payload generated by an agent node. |
| `node_status` | `{node_id, status:"done"|"failed"}` | Final completion status for a specific node. |
| `error` | `{error, data:{message}, node_id}` | Error notification if a node or process failed (node\_id absent indicates a core engine failure). |
| `done` | `{run_id, workflow_id, status:"success"|"failed", nodes:{id:status}}` | Final summary of the entire workflow execution. |
